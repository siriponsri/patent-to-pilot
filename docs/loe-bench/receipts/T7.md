## Evidence

- The selector used the FIX1 `build_entities` output and the same original-product eligibility rule to collect native product fields. The reverse indexes included NDA and ANDA keys outside the development cohort, including ANDA-only keys and applications without retained final approval. Only sampled development keys received verdicts. The process read the public raw FDA snapshot and did not open a protected evaluation split.
- Merge flags compare distinct nonempty application substance sets and native product sets after collapsing familiar trailing salt, ester and hydrate terms for screening. The screen preserves names made entirely of such tokens, including standalone electrolytes. Split flags use shared UNII or case- and punctuation-normalized substance names. A combination flag requires multiple components supported by the native set or existing key. Multiple flags may attach to one key. Sampling assigns each key once, in merge, split, combination, then remainder order. Sorted pools and Python's seeded random sampler use seed 20261128 with quotas of 25, 25, 20 and 30. No quota shortfall occurred.
- The executor assigned verdicts using the cited local `application_number`, product number, active ingredient fields and, when available, harmonized identifiers. Shared ingredients across different full sets do not establish a split. A retained salt descriptor can still yield correct grouping if there is no duplicate key for the same full set. Where FDA evidence supported two forms of the same active moiety, the forms were treated as the same moiety. A direct merge took precedence when both error types affected the same sampled key. Label or historical ambiguity and isolated omissions without an established collision or duplicate remain unresolved. See the per-row notes and supplemental locators. [21 CFR 314.3 active-moiety definition](https://www.ecfr.gov/current/title-21/chapter-I/subchapter-D/part-314/subpart-A/section-314.3) · [openFDA harmonized fields](https://open.fda.gov/apis/openfda-fields/)
- For example, NDA019011, NDA019797 and NDA203595 collide after the key erases distinct listed electrolytes from the PEG 3350 formulations. ANDA202414 splits the irbesartan/hydrochlorothiazide pair by including a compound text field in addition to the two individual ingredient names. The retained first ANDA is the same after repair because ANDA077446 has the same approval date. For NDA019763, Orange Book product 003 separately dates ifosfamide plus mesna to 1992-10-10, after the mixed application's retained original submission date. This is corroboration of the union problem. It stays outside the Drugs@FDA replay counts because a consistent product-level reconstruction was unavailable.
- Python 3.12.10 verified the Drugs@FDA SHA-256 values against the S0 manifest before loading them. The Orange Book NDA snapshot supplied targeted corroboration. The Orange Book ANDA 2010s file was inspected for schema only. The audit's numeric replay uses Drugs@FDA `ORIG/AP` records, including ANDA-only keys newly linked by an override. The no-override replay matched both original endpoints for every entity. A rerun from the checked-in reviews reproduced all three artifact SHA-256 values.

## Failures and limitations

- OpenFDA annotations are application-level and can intermix ingredients from different formulations or labels under one number. For example, ANDA202111 has a mexiletine label annotation alongside a native pemetrexed product and an FDA review that supports pemetrexed. The application or label identifier alone cannot establish identity. The audit treats such conflicts case by case. It has one executor and awaits independent planner review.
- Current snapshot records can lack dated native products and complete historical status histories. Ten confirmed error cases remain unavailable for date replay, including the union of separate products in one undated application and a conflicting helium/oxygen product annotation. A precise current date from one edition can corroborate a mismatch without establishing the historical minimum. The eight observed date changes therefore cover only the replayable cases.
- Rates describe entity-key adjudication on the development sample. Some errors involve undated or tentative alias records and have no observed effect on final approval dates. The 29 override rows are proposals. A blank application field denotes an exact-string mapping across applications, and a populated field limits the mapping to that record. Several mixed-product repairs need product-level evidence beyond a string mapping.
- Model scoring, test-set analysis and changes to the production normalizer were outside T7.
