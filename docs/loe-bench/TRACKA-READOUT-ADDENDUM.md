# Track A readout clarification for registration review

29 November 2026. This prospective repository addendum documents the custody rule for [OSF registration P2SMD](https://doi.org/10.17605/OSF.IO/P2SMD). It precedes the first outcome maturity on 27 November 2027. The filed registration and updates govern the endpoint, arm assignments and statistical rules. [Round 4 review](reviews/EXTERNAL-REVIEW-R4.md) · [Predeclared protocol](receipts/TRACKA-READOUT5-PROTOCOL.md).

The first attested capture release for each horizon fixes the FDA bytes used in that horizon's readout. The scope is the registered GitHub repository, Zenodo version DOI, OSF update 4 freeze-manifest digest and horizon. From maturity through seven UTC days after it, the workflow can stage the first covered Drugs@FDA edition, the FDA download index and the Orange Book edition named in that index. The workflow captures and attests bytes before it computes outcomes. It publishes capture and result as separate releases. Once a draft or signing record exists, recovery uses its exact bytes. Scoring and replay read the preserved FDA bytes. The result marks capture and scoring timing against maturity.

The first attested 12-month result is descriptive only. It supplies the M3 minus B1 panel for H3. The first attested 24-month result uses its own verified capture and that earlier panel. H1 must pass before H2 is reached. H3 can be tested only at the 24-month readout (on or after 27 November 2028) and only if H1 and H2 both pass. The registered one-sided level remains 0.025. Before publication, a missing or disputed capture or a missing or disputed required first 12-month result gives `UNRESOLVED_CONTINUITY`. Report descriptive estimates from available verified or explicitly supplied data. Local baseline, caller snapshots and current results before publication are provisional. [Scoring guide](HOW-TO-SCORE-TRACK-A.md) · [Measure map](TRACKA-MEASURE-MAP.md).

After publication, the first 24-month aggregate keeps its original bytes, decisions and UTC publication date permanently. Replay and recovery reports identify it as formal as verified at publication on that date. Each run also repeats canonical 12-month discovery under the original witness rules. The check reports `VERIFIED_CONSISTENT` when both digests match the archived H3 reference, `CURRENT_DISPUTE` when result pins disagree or a verified result differs from that reference, and `UNRESOLVED_CONTINUITY` when verification otherwise fails. The check includes the available witness and lookup locators. The custodian reconciles disputes and unresolved evidence. The published family stays intact during reconciliation. [Post-publication protocol](receipts/TRACKA-READOUT7-PROTOCOL.md).

The trusted default-branch custodian controls the workflow and must preserve its serialized publication path. GitHub Actions attestations bind each bundle digest and a deterministic scope witness to the workflow identity, repository and signing time. Discovery verifies the scope, signature, workflow ref, run and commit. Scored issue pins provide additional witnesses. The release, signed statements and scope witness must be retained independently. GitHub's public attestation index can locate an intent after mutable release records disappear. The public Sigstore log verifies retained bundles. Continued public indexing and the completeness of the retained record are custody assumptions. [GitHub artifact attestations](https://docs.github.com/en/actions/concepts/security/artifact-attestations).

When the release, tag and issue are gone and no attestation or other independent record establishes the first publication, set `TRACKA_CONTINUITY_HOLD=true` and record `UNRESOLVED_CONTINUITY`. Report any newly calculated estimates descriptively. An empty lookup cannot establish continuous custody after known or suspected record loss. A surviving signing record with missing bytes requires exact recovery against that digest before use. Keep the issue and release locators, archived bundle, signature and verification record together.
