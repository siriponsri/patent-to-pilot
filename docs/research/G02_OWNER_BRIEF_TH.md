# G02: เราจะพิสูจน์อะไร และมีประโยชน์กับงานเภสัชอย่างไร

24 ตุลาคม 2026 · สรุปสำหรับเจ้าของโครงการ · ปิดงานวางกรอบวิจัย ยังไม่ใช่ผลทดลอง

**ข้อสรุป:** ทำผลิตภัณฑ์ต่อได้ แต่เหตุผลทางวิจัยควรอยู่ที่ “ระบบช่วยลดการแก้เรื่องเดิมซ้ำในโครงการใหม่ และแก้เอกสารที่ได้รับผลจากเงื่อนไขใหม่ได้คุ้มกว่าวิธีง่ายหรือไม่” การบอกเพียงว่า agent จำองค์กรได้ ค้นสิทธิบัตรแบบปรับตัว หรือมีแผนผังเชื่อมข้อมูล ยังไม่พอเป็นความใหม่

## งานเดิมทำอะไรไปแล้ว

บทความด้านการค้นสิทธิบัตรของ Oltra-Garcia สอนให้ปรับวิธีค้นจากสิ่งที่เจอระหว่างทางตั้งแต่ปี 2018 ส่วน PatExpert เชื่อมการวิเคราะห์สิทธิบัตรกับการสร้างสมมติฐานแล้ว งาน ACE สะสมคู่มือจากประสบการณ์ และ PolicyBank รับคำแก้ไขหลังงานเพื่อนำไปปรับการใช้กฎในงานถัดไป งาน ESCROW กับ GCJR ก็ศึกษาการแก้เฉพาะส่วนและการตรวจว่าอะไรได้รับผลแล้ว จึงไม่ควรอ้างว่าเราเป็นคนแรกที่ทำสิ่งเหล่านี้ ดูตำแหน่งหลักฐานแต่ละงานใน [ตารางแหล่งอ่าน](G02_SOURCE_COVERAGE.md)

งานใหม่ที่เจ้าของส่งมาเพิ่มยิ่งทำให้ต้องจำกัดข้ออ้าง: **SkillOpt** ของทีม Microsoft และผู้ร่วมวิจัยมีวิธีปรับคู่มือของ agent จากงานที่ทำแล้ว ส่วน **HarnessOpt-Bench** ของ Scale AI เป็นชุดประเมินการปรับระบบรอบโมเดล ซึ่งรวมทั้งคำสั่ง เครื่องมือ ความจำ และลำดับงาน ดังนั้นการบอกว่าเราใช้ memory แทนการแก้ code ไม่ใช่จุดต่างที่พอจะอ้างความใหม่

แนวทางที่คุ้มกว่าคือใช้วิธีปรับปรุงที่มีอยู่เป็นฐาน แล้วตรวจว่าพอใช้กับโครงการสิทธิบัตรจริง ระบบยังรักษาที่มา แยกกฎแต่ละองค์กร และรับมือกฎเก่าที่ถูกแทนได้ดีเพียงใด ถ้า SkillOpt แบบเดิมทำได้พอแล้ว เราก็ใช้มันเป็นส่วนหนึ่งของผลิตภัณฑ์ได้ ไม่จำเป็นต้องประดิษฐ์ตัว optimizer ใหม่

สิ่งที่ยังต้องทดสอบในบริบทของเราคือ เมื่อเปลี่ยนจากงานตัวอย่างหนึ่งไปสู่อีกโครงการที่ใช้สิทธิบัตรคนละกลุ่ม ระบบยังใช้บทเรียนขององค์กรถูกเรื่อง ถูกองค์กร และไม่เอาข้อมูลเก่ามาอ้างแทนหลักฐานใหม่หรือไม่ ข้อนี้เป็นคำถามที่เสนอจากชุดงานที่อ่าน ไม่ใช่ข้อพิสูจน์ว่าไม่มีใครในโลกศึกษาแล้ว

## ตัวอย่างใกล้งานเภสัช

สมมติทีมกำลังเปรียบเทียบแนวทางพัฒนาระบบนำส่งยา ทีมแจ้งเงื่อนไขชัดว่า “กระบวนการบางอย่างต้องจ้างภายนอก ไม่ได้ทำเองในหน่วยงาน” นี่เป็นเงื่อนไของค์กรสมมติสำหรับการทดสอบ ไม่ใช่ข้อมูลจริงของ NCATS หรือบริษัทใด

ครั้งแรกระบบเสนอแผนที่เข้าใจผิดว่าทีมทำเองได้ เราให้คำแก้ไขที่ยืนยันตามเงื่อนไขนั้น พอเริ่มโครงการใหม่ ระบบควรแยกงานในทีมกับงานจ้างได้ถูกต้องและระบุสิ่งที่ต้องถามเพิ่ม แต่ยังต้องอ่านหลักฐานของสิทธิบัตรใหม่ ไม่เอาผลผลิตหรือคุณสมบัติจากโครงการเก่ามาใช้เป็นข้อเท็จจริงของโครงการใหม่

เพื่อดูว่าการจดจำช่วยจริง เราต้องเทียบกับวิธีที่ง่ายและเป็นธรรม: ให้โมเดลอีกชุดอ่าน **คำแก้ไขชุดเดียวกันทั้งหมดในคำสั่งโดยตรง** ถ้าวิธีง่ายทำได้เท่ากันและถูกกว่า ผลที่ควรได้คือใช้วิธีง่ายในผลิตภัณฑ์ ไม่ต้องเพิ่มความซับซ้อนเพื่อให้ชื่อว่า agent เรียนรู้

อีกคำถามหนึ่งเกิดในโครงการเดิม เช่น ต่อมาใช้เครื่องมือบางอย่างไม่ได้ หรือถอนเอกสารรองรับหนึ่งฉบับ ระบบควรแก้แผนทดลองและชุดส่งต่องานที่พึ่งสิ่งนั้น พร้อมคงส่วนที่ยังใช้ได้ การขาดข้อมูลผลผลิตหนึ่งช่องไม่ควรหยุดเอกสารทุกส่วน และการแก้เคสเดิมได้ยังไม่ใช่หลักฐานว่าเรียนรู้ข้ามโครงการแล้ว

## จะทดสอบแบบไหน โดยไม่ต้องหาผู้เชี่ยวชาญมาทำเฉลย

| คำถาม | วิธีเริ่มที่ตรวจได้ |
|---|---|
| จำคำแก้ไขไปใช้ในงานใหม่ได้หรือไม่ | ให้คำแก้ไขที่ตรวจได้จากกฎที่ประกาศหรือข้อความต้นฉบับ แล้วทดสอบกับโครงการใหม่ที่แยกกลุ่มสิทธิบัตรจากงานก่อนหน้า |
| ดีกว่าแค่อ่านคำแก้ไขหรือไม่ | เทียบไม่มีความจำ, อ่านคำแก้ไขทั้งหมดตรง ๆ, วิธีเดิมอย่าง SkillOpt และความจำที่แยกตามองค์กร โดยใช้ข้อมูลและงบเท่ากัน |
| แก้แผนเดิมได้ครบและไม่ทำส่วนอื่นเสียหรือไม่ | เปลี่ยนเงื่อนไขที่ระบุชัด แล้วตรวจช่องที่ควรแก้ ช่องที่ต้องคงเดิม และเอกสารที่ยังอ้างได้ |
| จำผิดองค์กรหรือยึดกฎเก่าหรือไม่ | ใส่องค์กรที่มีเงื่อนไขต่างกันและกฎที่ถูกแทนรุ่น ตรวจว่าระบบแยกได้หรือรายงานข้อขัดแย้ง |
| คุ้มค่าหรือไม่ | รวมเวลา คำขอโมเดล และค่าใช้จ่ายของการสร้าง/อ่านความจำ การค้นซ้ำ และงานที่ล้มเหลวด้วย |

จำนวนคำแก้ไข 0, 2, 5 และ 10 ครั้งเป็นจุดเริ่มที่เสนอสำหรับการออกแบบ ไม่ใช่ผลที่ทำแล้วหรือขนาดการทดลองสุดท้าย ทุกคำแก้ไขต้องใส่ในบริบทของวิธีเปรียบเทียบได้ครบ เพื่อไม่ให้ระบบเราได้เปรียบจากการที่อีกวิธีอ่านข้อมูลไม่ครบ ก่อนใช้ชุดทดสอบใหม่ให้ตรึงความจำไว้ ไม่เอาคำตอบหรือผลจากชุดทดสอบกลับมาแก้ระบบระหว่างวัด

**ผลที่สนับสนุนแนวทาง:** งานใหม่ผิดตามกฎที่ตรวจได้น้อยลง หรือได้ความถูกต้องเท่าเดิมด้วยต้นทุนต่ำลง โดยไม่เพิ่มปัญหาการอ้าง source หรือจำผิดองค์กร ผลต้องเทียบกับวิธีง่ายด้วย ไม่ใช่เทียบกับระบบไม่มีความจำเพียงอย่างเดียว

**ผลที่ทำให้ลดข้ออ้าง:** อ่านคำแก้ไขตรง ๆ ให้ผลพอกันและถูกกว่า, ความจำพากฎผิดองค์กรมาใช้, หรือ graph ช่วยได้เพราะแอบใช้เฉลยที่ระบบจริงไม่มี หากข้อมูลยังน้อยจนแยกผลไม่ได้ ให้รายงานว่ายังสรุปไม่ได้ ไม่บังคับให้ผลเป็นบวก

## สิ่งที่ผลนี้ยังไม่รับรอง

ผลตรวจข้อความและกฎช่วยยืนยันความสอดคล้องของเอกสารได้ แต่ไม่ยืนยันว่าผลิตได้จริง ปลอดภัย มีประสิทธิผล ผ่านกฎระเบียบ หรือไม่มีปัญหาสิทธิบัตร การมีข้อความในสิทธิบัตรไม่ได้ยืนยันผลทางวิทยาศาสตร์ และความรู้เภสัชกรของเจ้าของช่วยเลือกและทบทวนโจทย์ได้ แต่ไม่ถูกเรียกเป็นผู้เชี่ยวชาญอิสระทำ gold standard

ผลิตภัณฑ์ยังมุ่งรับเอกสารองค์กร หาโอกาส เปรียบเทียบเส้นทางพัฒนา และร่างชุดส่งต่องาน R&D/RA/Clinical Research เหมือนเดิม งานวิจัยเพียงแยกให้ชัดว่าเราวัดส่วนใดได้ World Patent Information ยังเป็นเป้าหมาย ไม่มีคำรับรองว่าจะรับตีพิมพ์
