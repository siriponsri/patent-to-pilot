# Research questions and data design freeze

**Effective 25 November 2026.** This is a prospective design decision. The questions, dataset roles, direction of improvement, comparison and decision rules below are frozen. Newly authored packets, source licences, population counts and execution manifests still need S1 receipts. No new experiment ran to prepare this document. Use [the master plan](MASTER-PLAN.md) for dependencies and [S1](01-research-data.md) for the materialization procedure.

## Questions and intended claims

| ID | Question | Observable answer |
|---|---|---|
| RQ1, primary | Given a Thai request and a fixed search budget, does using the compatibility of evidence across clauses or versions to choose between preserving results, reranking and acquiring a missing source increase scope-complete success over a coverage controller with a compatibility reranker? | Paired difference in the primary endpoint on controlled Thai DEV packets. Include both directions of each controlled change. |
| RQ2, mechanism | Which decisions recover valid evidence outside the initial pool, and which decisions discard valid evidence, mix scopes or search unnecessarily? | Compare three pool states, log recoveries and displacements, and disable the compatibility signal only at action selection. Keep the reranker and the tools identical. |
| RQ3, transfer | Does the frozen decision policy also work on English patent clauses when the document adapter supplies claim ancestry and embodiment identity? | Evaluate the original policy with a patent adapter before domain tuning. Show separate controlled-packet results, followed by a separate optional patent-tuned DEV row. |
| RQ4, continuity | Does structural acquisition improve patent-family retrieval and help a reader reach the first known cross-domain family earlier? | Independent historical scoreboards for P2 ALL Recall@200, IS1/Paper 53 strict OUT nDCG@100, early reach, first-hit rank and no-hit rate. |

The engine uses per-request conditions, typed evidence units and allowed relationships. A quote from a different date, version, example, table or claim branch may match a condition individually. The proposed policy treats a collection of such matches as incomplete until compatible witnesses exist. The engine may search again, rerank the current pool or return its existing evidence with the missing condition identified. The user-facing node/edge view is a projection of this record. It is never an input assembled from evaluator labels.

## Sampling, supervision and splits

- Use three disjoint pools of source families for public demonstration, optimizer development and reserved DEV evaluation. Within optimizer development, keep edit proposals and edit-selection validation on different families. A family groups statute versions/amendments, patent relatives, translations, paraphrases, altered siblings and synthetic descendants of any original. Where template leakage is plausible, group by template or agency too. Published examples belong with demonstration or optimizer development.
- Assign groups before writing ranking code or looking at outcome numbers. Record sorted family IDs, assignment seed/algorithm, duplicate policy, pair IDs and hashes in a signed-off data receipt. A pilot of ten source families is a design starting point. Expand when task diversity, rights and precision justify it. Make small or incomplete samples explicit.
- Include all three initial-pool states: compatible evidence present and well ranked; compatible evidence present but displaced; plausible matches present but a compatible witness outside the initial pool. The full approved corpus must contain a recoverable witness for the primary scenario. Also include independent unanswerable or genuinely ambiguous cases as an abstention diagnostic. The runtime receives the same corpus and initial pool across arms for a request; it never receives these state labels.
- Each controlled pair contains one substantive edit with a predetermined change in the decision or its necessary evidence, or a meaning-preserving edit with a predetermined invariant decision. Counterbalance edit position and changed/unchanged pairs. Derive truth from the independently specified edit. When two natural interpretations remain possible, request human adjudication, allow equivalent evidence sets, or assign `UNADJUDICATED` before running. Never infer absence from an unjudged natural document. Keep natural-document results separate from controlled truth.
- Keep evaluator-only decisions, gold sets, scope keys used as labels, expected pair changes and pool-state labels in a separate store. Evidence types and explicit references available in the original source are valid runtime features. A release fixture is never promoted to independent evaluation.

## Primary endpoint and decision rules

**Primary unit:** one answerable controlled Thai DEV request. The engine receives a fixed cap of four retrieval actions including the initial retrieval and may return at most eight source-bound evidence units. Stopping early is allowed. All arms share the candidate-depth cap, document view, model revision and ceilings for inspected units, tokens and wall time. S1 must pin the concrete remaining ceilings, tie policy and hardware/resource accounting before any timed or scored run. Report actual use. Source ingestion has a separate cost ledger.

**Scope-complete success** is binary. At least one acceptable annotated witness set must be present in the returned evidence, support every required condition under a permitted scope assignment, and support the returned decision. A decision that uses an incompatible or contradictory unit as support, a missing locator, an abstention on an answerable case, or a budget overrun scores zero. Irrelevant distractors merely displayed as alternatives do not imply support. Audit only units the engine used to justify the decision. Scorers must allow predeclared equivalent evidence and report excluded ambiguous cases and their denominators.

Report paired success differences in each of the three pool states. The primary estimate is their equally weighted mean versus **coverage-driven acquisition plus a compatibility reranker**. Absence of any state limits the result to a feasibility readout. Prespecify family-cluster bootstrap intervals, preserving pairs, using 10,000 replicates and seed 20261125. With too few independent families, publish counts and identify the interval as unstable. Report English transfer, natural documents, never-found queries and the separate historical scoreboards with their own denominators.

- **Feasibility closes a phase** when the promised runnable artifact and a truthful outcome exist. A zero or negative result parks that arm and keeps product work eligible to proceed.
- **One optional follow-up** is permitted by a strictly positive paired primary DEV estimate with valid provenance and matched budgets, even when its interval crosses zero. Mark it exploratory. Freeze the selected policy, eligible disjoint DEV families and the follow-up budget before scoring. No repeated selection on those same families.
- **A supported gain** requires the frozen contrast, paired interval lower bound above zero on the stated cohort, separate natural-data limitations and disclosure of costs, abstentions, displacements and regressions. A controlled DEV gain supports only that population. A missing independent assessment remains pending.
- **Historical comparability** retains every published predecessor gate. P2's +0.010 ALL Recall@200 and its confidence/IN/OUT guards apply only to the named historical score-win claim. The new primary and its lighter progression gate never revise P2-T04.

Any change to questions, scenarios, comparator, threshold, scoring or source assignment after this freeze needs a dated, versioned rationale before the affected measurement. Preserve the former protocol and all failed attempts.
