## Install and launch

Use a Windows source checkout and Python 3.12 with SQLite FTS5. The core runtime requires the `pydantic` and `jsonschema` dependency sets. The QA reconstruction downloaded versioned wheels from PyPI once, then installed from a local wheel directory using `--no-index`. Use the manifest's **base runtime** wheel rows as the exact closure. In PowerShell, with the wheel directory available as `$wheels` and a fresh store location as `$qa`:

```powershell
py -3.12 -m venv .venv
$manifest = Get-Content docs/evidence-scope/receipts/S4-release-manifest.json -Raw | ConvertFrom-Json
$runtime = @($manifest.wheel_manifest | Where-Object group -eq 'base runtime')
foreach ($wheel in $runtime) {
  $path = Join-Path $wheels $wheel.filename
  if ((Get-FileHash -LiteralPath $path -Algorithm SHA256).Hash -ne $wheel.sha256) { throw $wheel.filename }
}
$pins = @($runtime | ForEach-Object { "$($_.name)==$($_.version)" })
& .\.venv\Scripts\python.exe -m pip --isolated --disable-pip-version-check install --no-index --find-links $wheels $pins
& .\.venv\Scripts\python.exe scripts/ptp_run.py --doctor --data-dir "$qa"
& .\.venv\Scripts\python.exe scripts/ptp_run.py --smoke
& .\Start-PTP.cmd --data-dir "$qa"
```

The test install used the above package closures with the project bounds `pydantic>=2,<3`, `jsonschema>=4,<5` and the QA tools `pytest>=8,<9` and `playwright==1.60.0`. It subsequently installed `pypdf>=6,<7` and `pythainlp>=5.4,<6` from the same wheel directory. The pinned extras resolved to pypdf 6.21.4 and PyThaiNLP 5.4.0. The existing Chromium binary was 149.0.7827.55, revision 1228. It was provided explicitly because Playwright 1.60.0's default revision 1223 was absent. Chromium is a QA dependency only. The bundled UI uses the operator's browser.

The launcher binds loopback and opens the browser when requested. The automated validation used `PTP_NO_BROWSER=1` to control the browser separately. Stop a regular launch with Ctrl+C, then reuse the same `--data-dir` to access reading history. The automation stopped its own processes by PID. For a portable single-user scope use the included reader presets and local lexical comparison. The core Workbench also accepts user-supplied UTF-8 text/Markdown (`.txt`, `.md`, `.markdown`) in an owner project via `--ingest`. Use documents the operator has permission to process.
