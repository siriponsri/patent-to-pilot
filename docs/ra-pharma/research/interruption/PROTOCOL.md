# Safe row completion under a two-read budget

This is a fresh exposed engineering comparison. It does not change any previous endpoint or use previous case outputs for method selection. Twelve authored Thai dossier packets form three separate family groups, with one case of each of four layouts per group. Split namespace, applicant, application and raw document identifiers across groups. Presentation order and opaque IDs use random seed 2026112603. There is no training or tuning split because all policies and forecast weights are fixed before capture. The four layouts are intentional mechanism strata, with equal counts, and have no claim to a population distribution.

Each request has two evidence rows and is initially accompanied by incomplete visible attachment descriptors. Authentic-looking Thai fixture headings are author-written. A locator record may reveal a new descriptor only after inspection. A locator alone cannot support either result. The runtime opens raw UTF-8 document bytes under a common interface, and the same scope verifier checks observed applicant, application, round, sequence and role in all arms. Visible exact fields can guide lookup. An unverified descriptor cannot make an outgoing assertion. No runtime data maps a requested row to its correct evidence. Only the separate generator-state key records which raw records actually support which rows.

| Layout | Prospectively controlled facts |
|---|---|
| Valid bundle | One visible exact report for the first request. An opaque second report is from an earlier version. A locator reveals a valid bundle containing both rows. |
| Stale bundle | The same visible routing shape. The opaque second report actually supports the second request. The inspected locator exposes a prior-sequence bundle, with a scope mismatch visible after inspection. |
| Direct | Two separately visible exact reports. A read of each suffices. |
| Unresolved | No valid current report. The locator is empty when opened and plausible opaque direct reports have invalid applicant or sequence scope. |

All policies see the same initial descriptor fields, same newly observed locator contents and the same bytes for every possible open. One open costs one action. Reopening is prohibited. Cap is two. Stop when both rows are supported or no permissible action remains. After a valid report the row state records a hash and exact locator. Maintain missing, rejected and unsupported outcomes separately. Material competing actions are present when an unresolved row can be pursued through both immediate reports and a deferred locator.

The fixed domain rule prefers a fully visible exact eligible report. Otherwise it chooses a relevant locator with two actions left, then the highest-ranked direct compatible report. The simple adaptive control uses the strongest estimated immediate completion based on the current available descriptors, taking a relevant locator with two actions left if it has no viable direct option. Both update after reading. The candidate chooses a two-step forecast using the same instantaneous direct estimates. Exact visible scope has weight 1. Incomplete visible scope has weight 0.5. An explicit scope mismatch is ineligible. Candidate scores a pair of direct reads by summing the per-row union of their forecast support weights. When both reads fit, a locator with advertised unresolved rows is forecast at 0.8 times the number of those rows, with no first-action completion credit. Weight constants are engineering assumptions. Use estimated first-action completion to break forecast ties, then the ascending SHA-256 of the opaque document identifier. Use the same neutral identifier tie rule after each fixed/adaptive rule's own scores. Do not update weights after observing outcomes.

The policies differ by construction for a descriptor set with one visible exact single report, one incomplete single report and a locator advertising two rows. Immediate greedy opens the exact report. The candidate's direct forecast is 1.5 and its locator forecast is 1.6. It therefore opens the locator. It can open a newly revealed exact bundle or revert to a direct report after observing a stale or missing pointer. This is the one mechanism under test. Coverage forecast is not a proof of evidence support.
