# Deterministic fixture protocol

Prospective R3 engineering check, revision 1. Use project-authored fictional data under the repository licence. The packet is an intentionally constructed challenge with zero natural cases. It has disjoint synthetic source IDs and subject IDs by case. It supplies no independent transfer denominator. The fixtures use a simplified structured evidence record and omit OCR, legal interpretation and model decisions.

All arms can open a visible candidate through one of four routes, then stop. Two opened passages and one handoff evaluation per case/arm are the limits. Read the same source bytes for a given candidate in all arms. Every planning step examines all unread candidates without sorting them. Prioritize by visible rank for single and fixed specialists. A learned skill can give precedence to one route per requested evidence role, with visible rank as fallback. Use the same neutral SHA-256 tie rule in all arms. All policies use the same stop rule. The reader stops when the requested topic is found or no candidate or budget remains. This structured topic-equality stopping rule deliberately permits harmful early stops when an earlier passage answers the wrong question about subject or edition. Implement the handoff gate after reading to keep reading parity in the ablation.

Training uses only training examples. Compare visible-rank preference with the four available routes for each observed requested role, reusing the exact reader and scope gate. Choose the strict best training improvement against visible rank for that role, with ties left at baseline when there is no unique winner. Freeze the learned map before opening the diagnostic runtime packet. Training evaluates five policy options, with at most two reads per training request/option. Its resource ledger includes runs, actions, candidate inspections, bytes and time. A trained artifact here is a fixture update and stays in research.

The fixed single agent and fixed specialists intentionally share rank and verification; the difference is the handoff boundary. Fixed specialists select origin by source type and hand off to the receiving specialist. Learned specialists add only the routing preference. Two ablations use the identical learned read trace. Role-off removes only the evidence-role check. Verification-off removes subject, role, issuer, jurisdiction and edition checks. D11 isolates a role-only mismatch, while D08 isolates an edition mismatch. Edition matching uses structured metadata and does not infer temporal applicability. Compare assertions as source ID plus bounded value, using a separate key of permitted evidence and a known-missing vs answerable distinction. Count support and errors at common answered cases, as well as full counts, and retain individual regressions. Report route-choice and no-choice counts at the first step, first-passage baseline ceiling, correct assertions, missing evidence, abstention, unsupported outgoing assertions, wrong-product attribution, early stops that forgo a known admissible unread source while still under the cap, reads, available candidate scans and bytes. D01–D04 echo the four training templates with new identifiers. D05–D11 are additional authored challenges. Report these strata separately. These deliberately authored cases receive no population confidence interval.

Run the worker against runtime files only. Capture exact trace and learned-skill bytes and seal them before the evaluation key is opened for scoring. Development runs and scientific originals use different paths. One canonical fixture output is sufficient; a read-only scorer replay verifies it. Bind the canonical output path to the freeze. Publish raw synthetic diagnostics and an engineering receipt. Do not run the depth benchmark or reserved measurement from this entry point.
