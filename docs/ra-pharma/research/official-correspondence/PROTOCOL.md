## Runtime and comparisons

All three policies receive the same opaque corpus, query bytes, locally extracted text and current-source page check at most three unique page opens per query. The common index reads all retained pages using PyMuPDF sorted embedded text and records extraction time, source bytes and page counts. Common indexing precomputes trigram and fixed cue descriptors for all 22 source pages. Per-query ranking of unopened pages accesses descriptors only. Window-evaluation counts include descriptors for unchosen pages. No search-index snippets or index titles enter the reader. Normalize NFKC, casefold, translate Thai digits to ASCII, remove whitespace and U+200B/U+FEFF, preserve punctuation. Header binding compares an actual first-page opinion ID, a queried agency appearing near a matching letter reference and evidence of a letter in the nearby text.

1. **Literal lexical.** Rank candidates by query-character-trigram support on opening pages, independent of IDs. Open candidate first pages to check linkage. Once bound, inspect available issuer-response pages in order.
2. **Exact composite with conflict check.** Rank by observed agency and reference agreement, breaking remaining ties with the same lexical order. Use a single exact header from immutable extracted evidence. If ambiguous or incomplete, open candidate page 1 before binding. Inspect issuer-response pages in order.
3. **Bounded adaptive.** Use the same exact composite and conflict handling. When available page slots cannot cover the estimated relevant issuer-response pages, prioritize pages by query trigram and generic disposition cues. It never reads the adjudicated quotes or changes the query.

A heuristic Council-response marker supplies the same eligible region and same passage extraction constraints to each arm. It can fail on older formatting or recognize an imperfect boundary. Record coverage and false or ungrounded outputs. Each attempted response returns up to two non-overlapping passages, at most 360 normalized Unicode code points apiece. Evidence carries opacity-preserving document ID, actual opinion ID, 1-based PDF page and zero-based normalized offsets. These constraints prevent whole-opinion inclusion from earning credit. Missing linkage, missing issuer-response region and empty answer each have explicit unresolved status. Runtime uses embedded text views only. Rendered pages and OCR jobs are counted as zero for the policies. Independent readers' visual checking is distinct. Prior work on rhetorical-role recognition informs the shared guard and does not imply novelty for parsing alone. ## Scoring and accounting

The primary is a per-issue exact source, requesting agency/reference and historical opinion linkage plus coverage of **every** independently keyed dispositive fragment at its designated page and occurrence. Score only extracts tied to opened source pages. Check source offsets and exact text against the pinned canonical extraction before semantic-key matching. Use distinctive short fragments and exact normalized containment at the keyed occurrence. Several required fragments may fit inside one extract. Packing validation accepts any positive number of required fragments that fits the shared two non-overlapping window envelope. This deliberately strict proxy does not validate the full legal meaning of surrounding text. Report all issued but incomplete linkages, nonmatching spans, unresolved issue rows, unknown key rows and known/total denominators. Report provenance strata, coverage and page opens per arm plus common indexing, timings, output bytes and evaluation overhead. Choose adapting versus exact as the single primary comparison, with literal lexical descriptive. No post-hoc threshold or case replacement. This design can expose saturation if a reliable header and short answer are already easy to locate.

A one-time execution requires the Planner's review of the exact commit and lock with opaque corpus and PDF byte hashes, independent query and key hashes, output path, code, and protocol. Capture once using create-only output and seal before invoking the separate scorer. No reserved TEST, remote API, model, GPU or external spending. Local caps are eight acquired PDFs of at most one MiB and 16 pages apiece, 3 opens per issue/arm and two output passages. Preserve failures and do not mutate a sealed original.
