# When does another read change the dossier?

Planner review opened 26 November 2026. The engineering question is whether a specialist can tell the next reader exactly which fact is still missing, which source may supply it, and which other dossier rows depend on it. The scientific question is whether that information changes reading decisions and improves independently checked outputs under the same budget. This is a design review. The [IS1 successor](RESEARCH-AUDIT-20261126.md) retains its own ranking endpoint.

## One dossier, three readers

Consider an applicant preparing a Thai registration dossier for a tablet. A dependent patent claim adds a coating limitation. The patent reader opens the referenced claim and keeps the added limitation attached to that branch. The regulatory reader receives a description of the claimed coating and a request for the applicant's own coating evidence. A patent example alone leaves the applicant row unresolved. The correspondence reader can draft a request for the missing attachment and link it to that row. The sender, document class, signature authority and template govern letter layout and emblem use. A reviewer can follow each draft sentence back to the evidence or missing item.

Each row carries the subject, evidence role, jurisdiction, edition, exact locator and the alternatives under which it holds. Reads can satisfy several rows when those fields agree. An alternative parent in a multiple-dependent claim stays separate from its siblings. A negative assertion needs evidence appropriate to that assertion. An unresolved row can become a precise request. A letter can refer to a pending item without upgrading its status. An FTO chart also needs territorial rights, legal status and product mapping before a professional opinion.

The learning unit is a decision about the next admissible read, such as opening a parent claim, another patent family, the applicable edition of a Thai requirement or the applicant's attachment. On training data only, a correction can change the priority or estimated cost of these actions. Evidence admission and professional sign-off stay fixed. The learned and fixed readers receive identical visible inputs, cache access and final verification. Log the candidate actions, chosen read, affected rows and remaining budget. This permits a reviewer to identify a real change in behavior.

## An analytical boundary worth testing first

For a request to return **all** mandatory claim passages, let U be the union of distinct passages in the required branches. Suppose each passage must be opened once to supply its versioned locator and each open costs one unit. A correct cold-cache reader must make at least |U| opens. Traversing each required branch with a shared cache makes exactly |U| opens when the dependency map is complete and locating the passages is free. Reordering these opens cannot improve that count. With incomplete dependencies, separately meter discovery, parsing and candidate inspection. This argument concerns passage opens under the stated assumptions, not total runtime.

There is an empirical question where there are genuine choices. For example, a request might accept either of two independently sufficient applicant attachments, and one of those attachments might also complete another row for the **same** product and edition. Alternatively, a reviewer with a fixed budget might ask for as many fully supported chart rows as possible, with all remaining rows explicitly open. For a list of every applicable claim branch, a reader must account for every alternative. It cannot turn that assignment into an easier existential question.

## A Thai source that can independently check a handoff

The Thai FDA Medicines Regulation Division publishes an [example tracking table for a THAIRIMS response](https://drug.fda.moph.go.th/operators-guide/submit-application-drug). The linked example is dated 10 September 2024, media ID `673722105321365504`, 31,521 bytes, SHA-256 `cf7a4e45068858898004c37139e3799c7551aa8beea6b7c32c9f54b1f8a2b2e6`. The Planner inspected the publisher's DOCX in memory. In `word/document.xml`, the first table's third and fourth rows, counting the header, use the same example application identifier. They identify the first and second replies by different submission sequences, `0000` and `0001`. The identifier on the initial submission row is different. These facts describe this published example only.

This gives the correspondence specialist a practical acceptance case. Asked to draft a reply for the second round, it should cite row four and keep the earlier reply in the case history. An identifier-only join returns two plausible reply rows. An application-and-sequence lookup resolves the requested row. The fixed control must perform that same lookup. A policy earns no architectural credit for rediscovering the key. A real reading choice occurs if the expected sequence is missing or conflicting and the system can seek a versioned source or ask the applicant. Fabricated mutations of this example remain development fixtures. Official authoring suitability and operator time savings need independent evaluation.

The first XML extraction inserted a space between adjacent Word text runs, rendering the first sequence as `000 0`. Reconstructing text within its paragraph yielded `0000`. Preserve leading zeros and never use XML presentation runs as field delimiters. Scope the identifier to each source row before considering dossier-level alias links. The example is exposed and excluded from any unseen-family evaluation. Source text and templates were not added to Git.

## What the controlled architecture comparisons established

The [three-specialist handoff receipt](https://github.com/siriponsri/patent-to-pilot/tree/a523e5422a2faef046772d6fcfd02d3990d5e61c/docs/ra-pharma/research/handoff-conformance) uses the Thai issuer's table structure with authored applicant documents. The Planner verified the capture and evaluator digests, the publisher DOCX and original trace `07bdf52a1596872e2404a8322a87000a5b8926bece93725fa414a034486a24be`. Both the fixed exact lookup and the versioned handoff chose the same sources in all six cases. Each issued three correct replies and made three correct requests for missing evidence. ID-only routing missed one available attachment. All three arms kept unsupported applicant results out of the outgoing reply. Use the exact lookup where the complete binding is available.

The next comparison used 12 authored Thai dossiers with two requested rows each. The three groups each repeated the same four designed layouts. There was no model training or natural applicant cohort. The review verified six input hashes, the label boundary, the exact private directory and the absence of an original before release of lock `d59d2b1bac6fea2460d2eacb1280ef84c7c1d1a5b733cc2d4701d909908ad494`. Each policy opened 24 records in total. All three completed 15 of 24 rows correctly, missed three answerable rows, correctly abstained on six rows lacking a valid witness and issued zero unsupported rows.

After the **first** read, safe completions were 3 for the forecast and 9 for either control. The forecast read 9,159 bytes against 10,389 for nearest-complete but inspected 60 descriptors versus 54 and ranked 81 options versus 36. These are different resource units. Runtime savings and population benefit remain unestablished. Preserve the prospective two-read result as NULL.

The two ambiguous layouts have opposite payoffs. In the simplified comparison of their two first-move strategies, let p be the chance that the locator leads to a current bundle. Going through it can gain one row when it is current and lose one when it is stale. Its expected difference is therefore 2p minus 1. The fixture set p to one half by design. This calculation describes these layouts and action budgets only. It suggests looking for a real, cheap sign of version or authority that predicts which path is worth opening. An evaluator-supplied type, document outcome or hidden ID is ineligible. If a real cue exists, give it to exact lookup and the simple conditional policy too, charge acquisition and indexing, and test once on different families. Merely increasing the number of favorable fixtures would change the question.

### Conditional upper bound for the ambiguous pair

The generator exposes three possible first actions in both ambiguous layouts. Treat opaque identifiers, applicant identity and shuffled presentation order as uninformative about the layout. Charge an open for the locator and another for its target. For an optimistic upper bound, grant the reader knowledge of the true layout **after** it commits to its first open. The maximum number of valid rows that can be supported after its second open is then:

| First open | Valid bundle | Stale bundle | Equal-mixture mean |
|---|---:|---:|---:|
| Known-current single report | 1 | 2 | 1.5 |
| Unverified single report | 1 | 2 | 1.5 |
| Locator | 2 | 1 | 1.5 |

A reader that starts with either report cannot reach the valid bundle through its locator in the single remaining open. Starting with the locator leaves room for just one report when its bundle is stale. Any randomized first choice independent of the hidden layout is a mixture of these three rows and obeys the same upper bound. The direct-then-unverified rule attains it without learning the layout in advance. The direct stratum permits two supported rows and the unresolved stratum permits zero. Under this balanced authoring model the resulting expected ceiling is 15 supported rows per 12 dossiers. The observed scores reached it. The argument explains the closed comparison retrospectively. It is neither a general impossibility result nor a finite-packet guarantee for a policy that memorizes identifiers. Additional evidence available **before** the first read changes the model and requires a new comparison.
