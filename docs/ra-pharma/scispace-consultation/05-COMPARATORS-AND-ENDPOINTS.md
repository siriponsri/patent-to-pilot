# Design constraints for the proposed benchmark

**Decision unit.** Use one operator, one decision at a stated date, one product or institution, and one admissible evidence packet. Ask for the action, decisive source locator or missing witness, scope and next owner. Define what constitutes an equivalent action before observing any output. A request for missing evidence may be correct. An unsupported advancement, wrong applicant, incorrect strength, mismatched payer or unsupported counsel clearance is a consequential error.

**Required comparisons.** Give the manual incumbent its normal checklist and exact lookup. Run ChatGPT and NotebookLM as separate product baselines on the same decision and permitted sources. Name the product mode and version or observation date. For local AI, propose a named model and deployable runtime, then compare the same model with a plain prompt and with the proposed workflow. This paired local contrast isolates the workflow contribution. Measure practical differences against each incumbent separately. No platform arm has yet run.

**Portable input and fair access.** Specify an offline-readable UTF-8 source manifest, version and content hash when permitted, exact locators, shared extracts and machine-readable outputs. Keep scorer-only judgments outside the prompts. Equalize source bytes, retrieval allowances, time and cost where possible. Log actual source opens, retries, truncation, inaccessible settings, backend limitations, quantization, hardware and wall time. If a platform cannot accept the same evidence or prevent extra retrieval, report the asymmetry and restrict the comparison. Treat missing source access, invalid output and wrong professional action as different outcomes.

**What would justify a paper or a product?** Propose one paired action-level primary endpoint and a way to adjudicate it independently. Report ties, wins, losses, unsupported actions, adjudicator disagreement and uncertainty at the independent case or family level. A useful paper could characterize a reproducible failure under conditions that practitioners encounter. A product direction needs evidence that the improved decision matters to a real role. Formatting, citation counts and a successful offline parse establish engineering properties. Operator time or demand requires operator evidence. Recommend a threshold justified by practical stakes and pilot uncertainty, and a stopping rule if the incumbent wins or ties.

**Evidence boundaries.** Separate a public descriptive feasibility check from any later held evaluation; preregister before selection. Do not reuse exposed D36–D39 cases as independent tests. Respect source rights before retention, keep private inputs offline and avoid inference about missing dossiers. Propose public alternatives or a scoped future permission request where access is essential. The current decision is whether to design a new study. [Owner criteria and early-stop decision](https://github.com/siriponsri/patent-to-pilot/blob/830457e6a36cf2f42a9bb658da6c2901b1be25a8/docs/ra-pharma/ip-pharma/D39-DECISION-REQUEST.md)

**Historical controls to carry forward.** Where retrieval matters, report candidate availability before reranking and keep fixed lexical, seed-only or complete-content controls when applicable. For claim tracing include a cached parent walk. For dossier routing include exact composite-key lookup. Name which control fits the operator decision. Prior local Qwen work is engineering experience for the project; a new task needs a new measured baseline.
