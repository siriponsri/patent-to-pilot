# R1 main-view corpus projection and input preflight

## Bounded package
Implement a curator-only corpus projection and prospective CPU input gate. Inputs for this package were authored fixtures and source code only. No actual corpus projection, mixed-label staging, query encoding, GPU work or scientific experiment was run. Frozen historical runners are unchanged.

The projection keeps exactly id, title, abstract, claims, visible_from and c3. It removes construction roles and all other fields. A new destination is exclusive; failed partial outputs remain and the completion receipt is written last. The original corpus identity must match the independently trusted A14 observation. Source is checked again after projection. Ordered families, passage ownership/text, passage builder source and counts must remain equal; only serialized corpus hash changes. Strict valid dates/CPC are required: a real invalid record stops staging rather than silently dropping it.

The runtime preflight first accepts only a staged dev metadata bundle, verifies the curator-pinned projection receipt digest and original corpus identity, checks the exact projected schema, then observes and compares projected corpus, vector, model/tokenizer and encoder-source identity. Changes to date/CPC are caught by the pinned projected file hash even though passage text is unchanged. The projection receipt digest must be delivered independently by the curator; reading and accepting a digest generated by the same runtime would defeat this boundary.

## Evidence
58 targeted synthetic tests passed, including 12 new preflight/projection cases; Ruff passed for the three changed Python files. Tests cover unchanged passage order, removed construction roles, valid-but-modified dates/CPC, text/order/vector/tokenizer changes, extra labels/roles, receipt tampering, protected manifest rejection before corpus/model access, and output/source refusal. A synthetic encoder file raises if executed; it is only hashed, never loaded.

## Limits and next actions
- This is a callable input gate, not a completed retrieval runner. Query text binding, immutable-input lifecycle and actual runner invocation before GPU initialization still need integration.
- Only the primary main corpus view is covered. Sensitivity views require separately declared opaque masks; do not reconstruct their target roles inside method runtime.
- Hash/strict-schema checks are not physical isolation. The trusted curator must stage mixed metadata outside agent label access and exclude protected sources from the development environment.
- Runtime files must remain immutable after checking; no claim of adversarial concurrent-mutation protection.
- Actual A03 incidence and baseline ranking parity remain NOT_RUN. Original tokenizer/order historical attestation remains absent; the new receipt cannot manufacture it.
- Next: finish the prospective dev runner/query contract; prepare a complete curator staging/isolation handoff; then run permitted actual dev integrity and parity checks. No R1 scientific completion claim.
