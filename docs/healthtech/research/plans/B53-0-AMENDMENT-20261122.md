# B53.0 amendment (22 Nov 2026): native DAPFAM comparison with the published paper. FROZEN before any B53.0 number

This document refines `B53-PREDECLARATION.md` §5 (B53.0). The commit that adds it is the freeze.

**Known beforehand:** the B53 Stage 1 and Stage 2 aggregates (strict OUT nDCG@100 per arm), and the paper's published
table values copied from arXiv v2 (2506.22141v2). The published Array version could not be read.

## 1. Scope executed now (CPU only, from the frozen B53 runs)

- **Task:** TAC → TAC document retrieval over the full 45,336-family corpus, all 1,247 queries, views ALL / IN / OUT. These
  are the three in-paper MTEB tasks `DAPFAM{All,In,Out}TitlAbsClmToTitlAbsClmRetrieval`.
- **Systems:** the frozen B53 runs, depth 1,000, own family not excluded (native behaviour):
  - F1 BM25 (k1 1.5, b 0.75, `[a-z0-9]+`);
  - F3 Arctic-embed-m-v2.0 fp16 (512 tokens, query prefix "query: ");
  - F0 patembed-base and F2/F4 RRF, as context rows. These have no published counterpart.
- **Deferred (need inputs not staged in B53):**
  - TA → TAC (needs the title+abstract query view);
  - Arctic int8 (the paper does not state its quantisation method);
  - bm25s with its defaults (k1 1.2, b 0.75; the paper's tokenizer is not stated).

## 2. Metrics (paper §5.2, eq. 1–2)

- nDCG@100 with binary gain (rel = 1 for every positive), log2(i+1) discount, ideal over all positives of the view.
- Recall@100 = |positives in top 100| / |positives|.
- Macro over queries with at least one positive in the view.
- **Sensitivity:** graded gain = relevance_score, if any score differs from 1.

## 3. Comparison rule

Published values (Tables 17 and 19, TAC → TAC):

| System | nDCG@100 ALL / IN / OUT | R@100 ALL / IN / OUT |
|---|---|---|
| Dense (Arctic, int8) | 0.3055 / 0.3477 / 0.0482 | 0.3627 / 0.4437 / 0.1311 |
| BM25 (bm25s, k1 1.2) | 0.2451 / 0.2759 / 0.0418 | 0.2820 / 0.3463 / 0.1117 |

- Within **±0.010** absolute → "consistent with the published value".
- Otherwise → "differs by Δ; matched re-implementation".
- No cell is called an exact reproduction, because the int8 method, the BM25 tokenizer and the paper's handling of queries
  without positives are not stated.
- Best-by-partition rows of the paper (Tables 9–11) are not used as a single baseline.

## 4. Use

B53.0 checks the evaluator and the pipeline. It selects nothing for G03 or later goals. DAPFAM stays a previously exposed
benchmark.
