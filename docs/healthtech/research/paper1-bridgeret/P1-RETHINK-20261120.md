## 1. สรุปสั้น

- ตามแผนเดิม fine-tune Qwen3-Embedding-0.6B บน OA citation ทั้ง 5 config แล้วได้ P1-DEV OUT R@200 ต่ำกว่าโมเดลเดียวกันที่ไม่ได้ฝึก ตัวที่ดีที่สุดคือ S\* = S2-t0.02 ได้ 0.2472 ส่วน Z-Qwen3 ได้ 0.2741
- ฝั่ง IN ลดลงเกิน 0.02 ในทุก config ทั้งบน P1-DEV และ VAL นอกโดเมนก็ลดลงชัดเจน (BEIR nDCG@10 ลด 0.10 ถึง 0.18)
- คู่เทียบที่แข็งที่สุดคือ PatEmbed-large แบบไม่ฝึก ได้ 0.3282 ห่างจาก S\* อยู่ 0.08
- ถ้าเดินตามแผนเดิมต่อ ผลที่เป็นไปได้มากที่สุดคือรายงานว่าการ fine-tune ไม่ช่วย ซึ่งเป็น boundary result แบบเดียวกับ Paper 53 อย่างที่เจ้าของกังวลไว้
- แต่ข้อมูลที่มีอยู่แล้วชี้ช่องหนึ่งที่ใหญ่กว่า PatEmbed ได้ OUT R@1000 = 0.5121 แต่ R@200 = 0.3282 แปลว่าสิ่งที่ค้นถูกจริงกว่า 18 จุดอยู่ในอันดับ 201-1000 แล้ว ปัญหาจึงอยู่ที่การจัดลำดับ ตัวค้นยังหาเจออยู่
- **ข้อเสนอ:** ย้าย Paper 1 ไปเป็น "deep-pool reranking ที่ฝึกจาก OA citation บนตัวค้นที่แข็งที่สุด" แล้วตั้งชุดข้อมูล P1 ทั้งชุดเป็น benchmark ส่วนผล BridgeRet เดิมรายงานเป็นแขนหนึ่งที่ลงทะเบียนไว้ (ดูหัวข้อ 5)

### 3.4 การตั้งค่าการฝึกที่ใช้จริง (จาก `train-config.json`)

- full fine-tune ทุก weight, AdamW lr 2e-5, warm-up 5%, linear decay, 1 epoch
- 29,993 task จาก subset 30k, batch 16 query, k=3 negative ต่อ query ทำให้มี 64 เอกสารต่อ batch, รวม 1,875 step
- bf16 บน A40 ใช้เวลาราว 3.5 ชม. ต่อ config, max_len 512, last-token pooling, left padding
- query prompt ตรงกับตอนประเมิน: `Instruct: Given a patent application, retrieve prior art cited against it\nQuery: `

## 4. ทำไม fine-tune ถึงแพ้ zero-shot

ข้อ 4.1 และ 4.2 มีหลักฐานรองรับ ส่วนข้อ 4.3 ยังเป็นสมมติฐาน

### 4.1 สิ่งที่ข้อมูลบอกตรง ๆ

1. **โมเดลเรียนส่วนที่เรียนได้หมดภายในราว 50 step** อีก 1,800 step ที่เหลือ loss ไม่ลดต่อ แต่ weight ยังถูกอัปเดตด้วย lr สูงสุด 2e-5 ผลคือ geometry เดิมของโมเดลเคลื่อนไปโดยไม่ได้อะไรกลับมา forgetting ทั้งฝั่ง IN และ BEIR สอดคล้องกับภาพนี้
2. **ฐานที่เลือกอ่อนกว่าคู่เทียบมาก** Z-Qwen3 ตามหลัง PatEmbed อยู่ 0.054 ก่อนฝึกแล้ว ต่อให้การฝึกไม่ทำให้แย่ลง ก็ยังต้องได้เพิ่มเกิน 0.054 ถึงจะชนะคู่เทียบ ซึ่งเป็นเพดานที่สูงสำหรับ 30k task
3. **S1 แย่ที่สุด** S1 ใช้ negative จาก BM25 อย่างเดียว ไม่มี dense negative เลย การอธิบายว่า "dense false negative คือตัวการหลัก" จึงฟังไม่ขึ้น ปัญหาน่าจะอยู่ที่การตั้งค่าการฝึกหรือป้ายกำกับมากกว่า

### 4.2 จุดที่ต่างจากสูตรที่ฝึก embedding ได้ผลทั่วไป

- batch เล็ก (16 query, 64 เอกสาร) ส่วนโมเดลตระกูลนี้ถูกฝึกมาด้วย batch ใหญ่กว่าหลายเท่า contrastive loss ที่ batch เล็กให้ gradient แกว่งมาก
- ไม่มีอะไรยึดโมเดลไว้กับฐานเลย ไม่มี LoRA ไม่มี weight averaging ไม่มี KL/distillation กับฐาน
- ป้ายกำกับเบาบาง OA citation คือ prior art ที่ examiner เลือกอ้าง ไม่ใช่ทุกฉบับที่เกี่ยวข้อง เอกสารที่เกี่ยวข้องจริงแต่ไม่ถูกอ้างจึงถูกนับเป็น negative ได้ทั้งจาก BM25 และ dense

### 4.3 สมมติฐานที่ยังไม่ได้ทดสอบ

- H-a: ถ้าลด lr หรือ step ลง หรือใช้ LoRA หรือ interpolate weight กับฐาน (WiSE-FT) อาจได้ผลเหนือ zero-shot
- H-b: ถ้าใช้ batch ใหญ่ขึ้น (เช่น ใช้ GradCache) ผลจะดีขึ้น
- H-c: ข้อจำกัดหลักอาจเป็นความจุของ bi-encoder เอง เพราะต้องบีบทั้งใบคำขอให้เหลือเวกเตอร์เดียว ข้อนี้ cross-encoder ไม่มี

## 5. ทางเลือกสำหรับ Paper 1

เกณฑ์ที่ใช้เทียบ: impact, ความเสี่ยง, ต้นทุน และความต่างจาก Paper 53

### ทาง A: เดินตามแผนเดิม (full-TRAIN S\*, ราว USD 8)

- ผลที่คาดไว้คือ S\* ยังแพ้ Z-Qwen3 และ PatEmbed paper จะออกมาเป็น "fine-tune บน citation ไม่ช่วย และทำให้ลืม" ตรงไปตรงมาแต่ impact ต่ำ ลักษณะเป็น boundary result เหมือน Paper 53
- ข้อดีคือ protocol สะอาดที่สุด และไม่ต้องทำ amendment

### ทาง B: ฝึกใหม่แบบกันลืมบน PatEmbed-large

- เปลี่ยนฐานเป็นตัวที่แข็งที่สุด ใช้ LoRA หรือ WiSE-FT, lr ต่ำลง และ batch ใหญ่ขึ้น
- ถ้าได้ผล จะเป็นตัวค้นเอกสารสิทธิบัตรที่ดีที่สุดบน benchmark 1M เอกสารที่คุม leakage ได้ impact ปานกลางถึงสูง
- ความเสี่ยงสูง เพราะกลไกที่ทำให้รอบนี้ล้มเหลว (ป้ายเบาบาง, loss ตัน) ยังอยู่ครบ ส่วนต้นทุน GPU ใกล้เคียงรอบนี้

### ทาง C (แนะนำ): deep-pool reranker ที่ฝึกจาก OA citation + ตั้ง benchmark

แนวคิดคือ PatEmbed หาเอกสาร OUT ที่ถูกต้องเจอได้ถึง 51% ใน top-1000 แต่วางไว้ใน top-200 แค่ 33% ช่องว่าง 18 จุดนี้เป็น headroom ที่วัดได้แล้วจากข้อมูลจริง ในขณะที่แผน BridgeRet เดิมไม่เคยเข้าใกล้ตัวเลขระดับนี้

- **วิธี:** ใช้ PatEmbed-large ดึง top-1000 แล้วให้ cross-encoder (Qwen3-Reranker-0.6B ซึ่งมีอยู่บน dr-train แล้ว) ที่ฝึกจาก OA 102/103 citation ของ TRAIN 2006-2009 จัดลำดับใหม่ วัด OUT R@200 เป็น endpoint หลักเหมือนเดิม
- **ทำไม cross-encoder ถึงมีโอกาสมากกว่า:** cross-encoder อ่าน query กับเอกสารคู่กัน เลยจับความเชื่อมระหว่างสาขาที่ไม่ได้ใช้คำเดียวกันได้ ส่วน bi-encoder ต้องบีบทุกอย่างลงเวกเตอร์เดียว (H-c) อีกข้อคือการฝึก reranker ไม่ไปแตะ geometry ของตัวค้นขั้นแรก ปัญหา forgetting แบบรอบนี้จึงไม่ไปกระทบ first stage
- **ต่อยอด Paper 53 โดยตรง:** Paper 53 พบว่าการ "สั่งด้วย instruction" แทบไม่มีผล และ pool top-100 ขาดเอกสาร OUT ไปมาก (257/692 pool เท่านั้นที่มี) ทาง C ตอบสอง open item ของ Paper 53 พร้อมกัน คือขยาย pool ให้ลึก (1000) และเปลี่ยนจากสั่งด้วย instruction เป็นฝึกจากป้ายจริง ข้อนี้ตรงกับที่อาจารย์ที่ปรึกษาต้องการให้ต่อจาก Paper 53 อย่างเห็นได้ชัด
- **ส่วน benchmark:** ชุด P1 ทั้งหมดเป็นของที่ยังไม่มีใครมีในขนาดนี้ ได้แก่ USPTO OA 102/103 citation, TRAIN 2006-2009 / TEST 2012, corpus 1M ที่ตายตัว, split แบบ family-aware, Challenge-1M ที่ปิดผนึก และ endpoint OUT ข้ามสาขา ข้อมูล USPTO เป็น public domain จึงปล่อยได้ แต่การปล่อยต้องรอเจ้าของอนุมัติ benchmark ที่ใช้ซ้ำได้มักถูกอ้างอิงมากกว่าวิธีเดี่ยว ๆ
- **ผล BridgeRet เดิมไม่ทิ้ง** รายงานเป็นแขนที่ลงทะเบียนไว้ในหัวข้อ "fine-tune bi-encoder ทั่วไปบน citation ทำให้ลืมและไม่ช่วย" เป็นผลรองที่มีประโยชน์ ไม่ได้เป็นพาดหัวของ paper
- **ความเสี่ยง:** reranker ที่ฝึกแล้วอาจขยับ R@200 ได้น้อย เพราะป้ายเบาบางเหมือนกัน และต้นทุน inference สูง (10k query x 1000 เอกสาร = 10M คู่) จึงต้องมี pilot ราคาถูกก่อน (หัวข้อ 6)

### ทาง D: เลิก fine-tune แล้วเขียนเป็น benchmark paper อย่างเดียว

- ความเสี่ยงต่ำ ใช้ผล zero-shot ที่มีอยู่ครบแล้ว แต่ไม่มีวิธีใหม่ impact ขึ้นอยู่กับว่าชุมชนรับ benchmark มากแค่ไหน

## 6. ลำดับงานที่เสนอสำหรับทาง C (ทุกขั้นมี gate)

1. **AM-7 (ประกาศก่อนเห็นผล):** เขียน amendment ที่กำหนดแขน reranker, ความลึก pool 1000, endpoint หลัก OUT R@200, กฎเลือก config บน P1-DEV และกฎหยุด แล้ว freeze ก่อนเห็นผล reranker ตัวไหนเลย ข้อดีที่สำคัญคือ P1-TEST ยังปิดผนึกอยู่ จึงยังได้การทดสอบ confirmatory ที่สะอาดครั้งเดียวเหมือนเดิม
2. **Pilot 0 (ไม่มีค่าใช้จ่าย, CPU):** บน P1-DEV ดูว่าเอกสาร OUT ที่ถูกต้องในอันดับ 201-1000 ของ PatEmbed กระจายอยู่ตรงไหน คือ ceiling ที่ reranker จะเก็บได้ ใช้ ranking ที่มีอยู่แล้ว ไม่ต้องใช้ GPU
3. **Pilot 1 (zero-shot reranker):** สุ่มตาม hash 1,000 query OUT จาก P1-DEV ให้ Qwen3-Reranker-0.6B ไม่ฝึก จัดลำดับ top-1000 ใหม่ ราว 1M คู่ ใช้ RunPod ราว USD 3-5 เพราะ V100 ยังติด B53 Stage 2 อีกราวหนึ่งวัน gate: ถ้า zero-shot reranker ขยับ OUT R@200 ไม่ได้เลย ให้หยุดทบทวนก่อนฝึก
4. **ฝึก reranker** บน TRAIN 2006-2009 (ใช้ task ที่ mine ไว้แล้ว 97,059 task ไม่ต้องดาวน์โหลดใหม่) แบบ grid เล็กบน subset เลือกบน P1-DEV ตามกฎ AM-7
5. **ทดสอบ confirmatory ครั้งเดียว** บน P1-TEST ตามแผนที่ freeze ไว้
6. เขียน paper: benchmark + reranker เป็นผลหลัก ส่วน BridgeRet bi-encoder เป็นผลรอง

## 7. สิ่งที่ต้องให้เจ้าของตัดสินใจ

1. **เลือกทาง:** A, B, C หรือ D (ข้อเสนอคือ C)
2. **ถ้าเลือก C ต้องขอเพดานใหม่:** pilot USD 5 ก่อน แล้วถ้าผ่าน gate ขอเพดาน run เต็มต่างหาก (ประเมินราว USD 30-50) ตอนนี้เพดาน P1 FT เหลือ USD 11.46 และจะยังไม่ใช้จนกว่าเจ้าของจะสั่ง
3. **การปล่อย benchmark สู่สาธารณะ** เป็น external release ต้องได้รับอนุมัติแยก ยังไม่ต้องตอบตอนนี้

ระหว่างรอคำตอบ ยังไม่มีงาน P1 ใหม่บน GPU และยังไม่มีการสร้าง pod ส่วน B53 Stage 2 ยังรันอยู่บน V100 ตามเดิม
