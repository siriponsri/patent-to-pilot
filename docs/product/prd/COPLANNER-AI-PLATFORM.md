# Market Window Dossier | AI assistance and platform decision

**Co-planner recommendation for the main planner and Product Owner, 28 November 2026.** Approve one static front end and one FastAPI gateway. Publish the open dossier reader on GitHub Pages. Run live AI for invited colleagues at one organization-controlled HTTPS origin and use that gateway for the Windows app. This is the shortest credible path to a real web and desktop demonstration by 15 December. Host, invitees and identity service still need the owner's decision. No hosting, inference, user trial or acceptance test was performed for this critique. ## Provider contract

Expose four typed tasks to clients. The gateway selects a configured provider, model, token cap and allowed capability set. Use a single Chat Completions client with provider-specific field mapping. Baseline transport is a non-streamed text response, parsed and validated locally. Tools stay off. Where a provider streams, buffer the entire response before validation and publication. Disable SDK retries and routing fallback by default. On failure, return a typed unavailable, abstained or rejected response. Log the actual model, upstream and cost evidence. A local-server migration also needs approved model rights, sizing, Thai evaluation and a new configuration receipt.

## Grounding, refusal and acceptance

1. The client identifies a released dossier, snapshot, horizon, language, task and question. The server loads a rights-cleared evidence manifest for that identity and cutoff. Exclude outcome/reveal fields, later editions, evaluator labels and private user material before forming the prompt. For the trial, map common A3 questions to open question templates locally and let users confirm the question sent. Unmatched free text stays on the device. Test the resulting coverage with colleagues before proposing broader free-text transmission.
2. Return one factual proposition per item with dossier claim IDs. Resolve each ID to its source ID, version, SHA-256 and exact locator in the server manifest. Reject foreign IDs, wrong edition or horizon, unsupported precision, fabricated links and merged assertions with incomplete support. Render links from the manifest. Fixed greetings, instructions and refusal text come from the UI. Keep status, subject, jurisdiction, polarity and uncertainty bound to each value.
3. Compare typed fields as tuples of entity, predicate, value, unit, jurisdiction and date role. Normalize Thai digits and explicit Buddhist Era dates with a reversible display rule. Reject ambiguous calendars, day precision invented from a year, swapped dates, changed denominators, dose-unit shifts and percent/probability confusion. Inject forecast numbers from canonical fields using the existing UI rounding rule. A matching numeral elsewhere in the cited text is insufficient.
4. A1 summarizes the US endpoint, uncertainty and next check. A2 draws its question, agency and role from the checklist. A3 answers within the selected dossier and gives the next source to consult when evidence is missing. A4 copies original-language text directly from an approved claim node and links each proposed element to character spans. Verify publication/kind code, jurisdiction, claim number, edition and dependencies. Show inherited parent claims. Label a Thai gloss separately. If the source, dependency or rights are missing, return a lookup task. An abstract or family match cannot supply the missing text. [USPTO XML specifications](https://www.uspto.gov/learning-and-resources/xml-resources)
5. Treat external text, titles and questions as untrusted data. Allowlist source fields, delimit evidence, escape all display text and give the model no tools, network, secrets or ability to send correspondence. Only the server selects URLs. Test instructions embedded in a cited passage, a misleading source title and a request for another dossier. Refuse the whole affected answer if dropping a sentence could change its meaning. Record raw validation failures and user-visible abstentions separately. [Greshake et al., indirect prompt injection](https://arxiv.org/abs/2302.12173)

**Freeze before inference.** Use 32 open development fixtures, eight per task, each with a distinct case/question ID. For each task fix five answerable and three must-abstain cases. Include unknown Thai status, a US/Thai jurisdiction swap, a changed horizon, a missing parent claim, a conflicting edition and an injected instruction across the set. Include Thai and English questions, Thai digits and a Thai letter. Freeze an offline human-written example of an appropriate referral and a checklist-only baseline for the same cases. Lock IDs, evidence and prompt hashes, model/route, expected facts, alternative acceptable evidence and grading rules before seeing outputs. Keep the evaluation key outside the gateway and keep held research data closed. Use separate mechanical fixtures for iteration. A changed candidate receives a versioned rerun and an exposed-sample label.

| Gate for the proposed release model | Unit, threshold and adjudication |
|---|---|
| Evidence and values | 100% of displayed factual propositions have resolvable citations. 100% of displayed numbers/dates match their typed evidence. 100% of displayed A4 quotations reproduce the canonical source span. Report counts and empty denominators as NOT_RUN. |
| Abstention and usefulness | All 12/12 required abstentions give an appropriate reason and next step. At least 4/5 answerable tasks **per feature** deliver the required facts or elements and a usable next action. Count refusal, provider error, malformed output and lost edits as failures on answerable cases. |
| Semantic support and Thai wording | Main planner checks every displayed proposition against the cited passage across all 32 outputs. Record fully supported propositions / factual propositions and relevant citations / citations used. Require 100% full support for published sample outputs and zero decision-changing errors, legal conclusions or reveal leaks. Check qualifiers, claim dependencies, agency, Thai gloss and audience. Accept equivalent wording and alternative valid evidence. Spot-check source-to-screen parity for one answerable and one abstaining case per feature, then follow an edited A2 through to the PDF. |
| What the numbers establish | Report counts per task, model and language, before and after filtering. The small fixed sample supports an engineering release decision. Human benefit, forecast improvement and Thai legal correctness require separate evidence. No LLM adjudicates correctness. |

Gao et al.'s ALCE benchmark motivates measuring citation completeness separately from citation relevance. Rashkin et al.'s AIS protocol motivates the human judgment that the cited source supports the complete statement. The thresholds above are proposed MWD gates. Neither paper validates them for Thai patent reading. [ALCE](https://arxiv.org/abs/2305.14627) · [AIS](https://doi.org/10.1162/coli_a_00486)
