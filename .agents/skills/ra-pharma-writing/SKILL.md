# Write for the person who uses the record

Write project documentation in English. Preserve original sources, translated glosses and issuer names as data. Thai correspondence generated by the product is a user deliverable. Keep credentials, private case text and protected evaluation data out of documentation and memory.

| Reader | Lead with | Verify before closing |
|---|---|---|
| Someone trying the software | One exact entrypoint, prerequisites, a case to open and the visible result | Exercise the documented path; distinguish the installed alpha from the roadmap |
| A researcher comparing methods | Cohort, evidence role, comparator, endpoint, budget and observed difference | Link the frozen protocol and receipt; identify denominators, uncertainty, exclusions, failed runs and any control with the same actions |
| A regulatory affairs operator | Applicant, product, jurisdiction, as-of date, requested action and missing items | Each material statement points to the appropriate source owner, edition and locator; show where review is required |
| The next executor | Branch, last verified state, unresolved decision, exact next action and owner | Check local and remote revision, artifact paths, job status and actual costs |

For a README, use a short purpose statement, an executable example, a verified-versus-planned distinction and direct links for evidence and licensing. For a diagram, label what each specialist reads or produces. Keep labels legible at README width. Use the existing project mark for project identity; reserve official emblems for permitted, correctly attributed document examples.

At every task close, update the affected instructions or user guidance, then the assigned HANDOFF and MEMORY records. In memory, record what happened, what evidence supports it, what failed or remains uncertain and the next action that prevents repetition. For a task with no new reusable lesson, record the checked outcome and reference the prior lesson. Keep one canonical account and link to it from the other records.

Examples: an unsupported applicant result stays missing even if a patent supplies a similar number. A failed search slot stays NOT_RUN even if an older cohort has a published score. A local rendered letter is an engineering artifact; claims of legal suitability or operator time savings need separate evidence.

Editorial references used for the README refresh: [uv](https://github.com/astral-sh/uv) for its compact opening and runnable install, and [DuckDB](https://github.com/duckdb/duckdb) for a recognizable mark, a concrete example and short paths to technical details.
